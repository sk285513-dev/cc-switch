## 🤝 三、 AI 溝通、交接與交付指導原則 (AI Communication & Handoff Protocol)

本條為使用者親自下達之最重要鐵律，任何接手之 AI 皆須無條件遵守：

### 1. 角色限制與專業分工 (Role Restriction & Delegation)
**非 Sonnet 模型 (如 Gemini) 絕對禁止主動修改或設計程式碼**。Gemini 的角色被嚴格限定為「文件整理、環境盤點與驗收檢查」的專業發包商。任何實際的程式碼撰寫與修改，必須保留給 Sonnet 等專門的 Coder 模型執行，Gemini 只能進行分析與任務交付，絕不准越俎代庖。

### 2. 溝通與文件交付原則 (Communication Rules)
* **未經允許，禁止刪改**：絕不准亂刪東西未經使用者允許，也不准寫東西未經使用者允許。這是最高原則。
* **先展示，後動作**：若判斷文件中有過時或無關工作的廢話需要刪改，**必須先把要修改的片段「框起來」展示給使用者看**，告訴使用者為何建議刪除。等待使用者明確下達指示後，才能真正動手寫入檔案。
* **交接交付規範**：除錯檔案必須打包為 `.txt`，直接存入 `C:\LocalAI_Workstation\`，讓使用者直接看得到。**嚴禁在檔案名稱加上時間戳記或版本號**（例如禁止加 `_20260802`），以保持檔名乾淨易懂。檔案的最新時間，直接依賴 Windows 檔案總管的「修改日期」即可。嚴禁在對話框洗版超過 50 行。

### 3. 帳號切換與交接規範 (AI Account Handoff Protocol)
* **第一優先讀取移交文檔 (Read README_DEVEL.md First)**：當新帳號、新代理人（Agent）或新執行緒首次進入或重啟本專案時，**必須在第一時間（首個步驟）讀取專案根目錄下的 `README_DEVEL.md`** 以掌握專案開發進度、現行系統架構與接下來的行動計畫。嚴禁在未讀取 `README_DEVEL.md` 的情況下，盲目修改現有 `scripts/` 下的程式碼或重複啟動已經在背景運行的轉譯佇列任務。
* **Quota 限制與切換帳號前置存檔機制 (Pre-Limit Handoff File Generation)**：當工作中的舊帳號（或當前 Agent 執行緒）偵測到快要觸發系統的 Baseline Quota 限制時（例如 API Key 輪替已接近上限，或當前工作站的 API 額度即將告罄），**務必先將最新系統進度、當前 Task ID 與下一步詳細行動計畫產出並更新至 `README_DEVEL.md` 檔案放回專案資料夾**。此「喚醒詞移交文檔」能引導隨後切換而來的新 AI 帳號在第一步讀取並完美銜接 100% 的專案記憶。

## 🏗️ 四、 系統任務分工與架構現狀 (System Architecture & Task Delegation)

### 1. 本地端（Local）的任務分工：重度 I/O 與影音預處理
本地端主要負責高硬體消耗、大檔案讀寫、以及圖像特徵偵測等不需要強大語言邏輯，但極度消耗 CPU/GPU 運算資源的底層操作：
* **音訊提取與規格轉換 (FFmpeg / 本地 CPU)**：直接讀取數 GB 的原始 MP4 影片，快速提取音軌，並降採樣為標準 16kHz 單聲道 WAV 格式，減輕後續上傳雲端的流量負擔。
* **智慧靜音切片 (Silence Detection / 本地 CPU)**：利用本機 CPU 分析音訊波形，偵測大於 1.5 秒且低於 -35dB 的靜音點，在老師說話的斷句邊界進行切片（限制在 12 分鐘內），避免粗暴切斷句子影響雲端語意理解。
* **影像偵測與板書裁剪 (OpenCV / 本地 GPU/CPU)**：本地以每秒 1 幀（1fps）的高頻率掃描影片，利用圖像差分法判斷老師何時在黑板上寫字，在畫面穩定後進行螢幕去噪、投影校正，並裁剪出乾淨的板書區域圖片，存放在本機快取。
* **向量資料庫與混合檢索 (Qdrant & BM25 / 本地 Docker)**：在本地部署 Qdrant 容器。本地計算稀疏向量與混合檢索（Hybrid Search），保障檢索的即時性。

### 2. 雲端（Cloud）的任務分工：高階語意理解與視覺 OCR
雲端主要調用 Gemini 2.5 Flash / Pro 大模型，負責語音聽寫、上下文同音錯字校對、大綱摘要、以及複雜圖表視覺解析：
* **分片語音轉寫 (STT / Gemini 2.5 Flash)**：將切好的 12 分鐘 WAV 音檔上傳至 Gemini Files API，由 72B 級別的語音多模態能力直接進行聽寫。在聽寫的第一步，就透過雲端強大的法律知識庫，將口語贅字過濾，並直接將同音錯字在源頭校正。
* **圖像板書視覺翻譯 (Visual OCR / Gemini 2.5 Flash)**：將本地 OpenCV 提取的乾淨板書圖片上傳，由 Gemini Flash 進行多模態識別，將黑板上的圖畫、複雜法律關係圖表翻譯成結構化的 Markdown 文字筆記。
* **全文語意精校與拼接 (Merge & Refinement / Gemini 2.5 Pro)**：將所有分片的逐字稿拼接，由擁有超大上下文的 Gemini Pro 閱讀全文，進行跨片段的語意流暢度微調，並自動生成整堂課的「精準章節大綱」與「核心爭點摘要」。
* **講義與板書深度融合 (Final Formatter / Gemini 2.5 Flash)**：比對板書圖片的時間戳記與逐字稿時間戳記，將「板書筆記」插入到逐字稿的對應段落中，渲染出最終排版精美的 Markdown 筆記。

### 3. 開發進度與已修復專案清單 (Development Progress)
* **多金鑰配額管理器 (QuotaManager)**：模組位於 `scripts/quota_manager.py`，管理 49 把金鑰（日上限約 980 次呼叫），跨進程共享 `config/quota_state.json` 狀態。當 API 遇到 429 限制時，會自動進行自適應睡眠冷卻，並在單分片失敗 3 次後輪替至下一組金鑰。

  * 實裝了 `0.6 ~ 1.5 KB/min` 的講義密度雙向防護網，精準攔截 Whisper 無限迴圈產生的幻覺垃圾檔案。

## 🚫 五、 開發與修改程式碼強制禁令 (Code Modification Safeguards & Bans)

### 1. 嚴禁自作聰明、重造輪子與過度工程 (No Reinventing the Wheel & Minimal Edit)
* **先尋找原版程式碼，絕不盲目新建**：當使用者提到「一鍵啟動」、「啟動腳本」或任何已存在的自訂功能時，Agent **必須先**在工作站目錄（`C:\LocalAI_Workstation\`）確實搜索原版腳本，或請使用者提供。
* **禁止擅自曲解使用者意圖與破壞性管線整合**：若使用者沒有明確要求，**絕對禁止**把一個腳本中數十行正常運作的本機處理代碼直接刪除，擅自幫它改成只有「佇列推播」功能的閹割版。如果檔案沒有進入管線，正確的做法是去檢查並擴充真正負責管線入口的腳本（如 FileWatcher），而不是殘害其他獨立工具。
* **直接給出差異，禁止自作聰明寫包裝腳本**：當使用者貼出一段原版腳本並指出某一行有問題時，Agent 必須「乖乖地」只針對有問題的那一行進行修正，並直接貼回對話框。**嚴禁過度工程**，絕對禁止為了一個簡單的 PowerShell 單行語法修正，就擅自跑去寫一個 Python 或 VBS 包裝腳本來逃避解決原腳本的問題。使用者要 `.ps1` 就給 `.ps1`！

### 2. 終端機、腳本語法與編碼強制規範 (Syntax & Encoding Rules)
* **無條件使用 PowerShell 語法**：所有提供給使用者直接複製執行、或用於終端機自動化的指令與腳本，**必須無條件且唯一使用 PowerShell (PS) 語法**。絕對禁止提供傳統 CMD 或 `.bat` 語法。啟動新視窗必須使用 `Start-Process`，註解使用 `#`。
* **無視系統底層編碼的愚蠢行為禁令**：任何給使用者在本機執行的含有中文字元的 PowerShell 腳本，**必須強制使用 `Set-Content -Encoding utf8BOM`** 寫入。若使用 UTF-8 無 BOM，會導致 Windows PowerShell (5.1) 執行時中文亂碼破壞引號或括號，造成 `Start-Process` 無聲閃退。
* **中文路徑處理**：所有 Node.js/Python 腳本呼叫必須使用 `execFile` 而非 `exec`，確保透過 Windows Unicode API（CreateProcessW/UTF-16）傳遞路徑，避免 CP950 字元集破壞中文路徑。

### 3. 備份污染盲點與除錯退回紀律 (Backup Taint & Rollback Protocol)
* **備份污染盲點**：當使用者指出「過去的 AI 寫了錯誤的假腳本」時，**絕對不要**跑去讀取舊日期的備份檔，然後把那個「已經被污染的錯誤腳本」當成真理還原。必須用「邏輯」判斷內容是否符合使用者真實需求，而不是盲信檔名。
* **Git Rollback 紀律**：若連續 3 輪除錯 Bug 未減或發生錯誤漂移，必須執行 Git Rollback 退回最近的安全綠色節點，重新審視底層問題，禁止繼續堆疊補丁。

### 4. 視窗代碼輸出禁令 (No Large Code Blocks in UI)
* 嚴禁在聊天對話視窗輸出超過 50 行的完整程式碼區塊，防止 KV Cache 爆炸。
* 所有程式碼變更必須靜默呼叫原生檔案寫入工具處理。

* **禁止憑直覺大幅跳變**：必須有數據支持，若要調整，最多 ±2 步進（如 10→8）。嚴禁超過實測上限導致全 503 thundering herd。
* **紀錄參數與效果**：每次調整後必須更新 `README_DEVEL.md` 記錄「日期、並發數、有效 key 數與實測 KPI」。
* **驗證金鑰**：每次加入新 key 前必須先驗證，防止死 key 長期消耗配額。

### 2. Windows 背景自動化與除錯規範 (Background Task Rule)
* **禁止踩坑 (0x800700E8 錯誤)**：在沙箱環境或系統排程中，使用 PowerShell 啟動帶有 GUI 介面或長時間背景待機的任務，極易因父進程切斷標準管道而觸發 0x800700e8 崩潰。
* **強制標準解法**：若需建立「背景監控程式」或「系統對話框」，**嚴禁**使用 PowerShell 腳本。**必須優先改用 Python (`pythonw.exe`)** 搭配 `ctypes.windll.user32.MessageBoxW`，或以 VBS 啟動器進行隔離。

## 🛡️ 七、 課程消化管線與資料防護 (Data Pipeline & Knowledge Management)

### 1. 課程消化與排程優先序 (National Exam Priority Rules)
所有處理法律課程的 Agent（如 `auto_ingest_bot.py`）在掃描教材時，必須絕對遵守「國考核心」權重標準（Score 越小代表越優先）。非白名單內的科目一律強制跳過：
1. **最高 (10分)**：憲法
2. **高 (20分)**：民法（含身分法）
3. **高 (25分)**：刑法
4. **高 (30分)**：行政法
5. **中 (40分)**：程序法（民事訴訟法 / 刑事訴訟法 / 家事事件法）
6. **中 (50分)**：土地法規
7. **一般 (60分)**：商事法（公司法 / 票據法 / 證券交易法 / 稅法）

### 2. 檔案與磁碟掃描防護禁令 (Drive & Extension Safeguards)
* **掃描磁碟白名單解鎖**：系統允許掃描本機所有有效的磁碟機 (A~Z 碟)，但**必須嚴格封鎖非國家考試「司法官與律師」等法律相關專業科目以外的雜訊檔案**（依賴 `is_file_content_legal` 判定）。
* **副檔名純淨化**：**絕對禁止**為了方便測試，將 `.txt`, `.pdf`, `.png`, `.jpg` 加入來源過濾清單中，這會引發嚴重的 2000+ 檔案重複吸收災難。

### 3. 法律知識防護與隱私 (Hallucination & Privacy Safeguards)
* **時效敏感性原則**：涉及消滅時效、除斥期間的計算必須使用系統的 DeadlineCalendar 知識庫，**禁止 LLM 自行計算時效**。
* **幻覺防護與引用完整性**：嚴禁直接輸出未經查證的法律引用。所有生成的法律文本必須附帶可驗證的條文引用，禁止使用「依相關法規」等模糊表述。
* **資料最小化原則**：日誌中禁止記錄姓名、身分證字號、案件當事人等敏感資訊，統一以 `[REDACTED]` 替代。

## ⚖️ 八、 系統終極法律品質與驗收標準 (Ultimate Acceptance Criteria)

**必須自動批次完成 30 份真實課程，全程無當機、無錯誤。所有任務的輸出必須達到以下嚴格標準：**

### 1. 檔案落地與實體存在性雙備份標準 (Physical Deliverables)
任務狀態標記為 `completed` 後，每個任務必須成功產生 5 個帶有課程前綴名稱的實體檔案，且必須確實、完好且持久地保存在 `A:\processed_md\` 中，**且同時自動複製一份備份至影片原始存放目錄（如 `J:\土地登記\ch1\` 等）**：
* `[課程名稱].md`：最終精校 Markdown 講義（包含逐字稿、階層大綱、核心爭點與板書筆記）。
* `[課程名稱].srt`：標準繁體中文 SRT 字幕檔。
* `[課程名稱].vtt`：標準 WebVTT 字幕檔。
* `[課程名稱].txt`：純文字逐字稿（去除時間戳記與口語贅字）。
* `[課程名稱]_index.json`：包含段落索引、主題摘要的結構化 JSON（供 RAG 檢索）。

### 2. 講義內容與法律專業品質標準 (Content Quality)
文字與格式必須達到臺灣法律實務的嚴格標準（正確率 ≥ 98%），任何違規皆視為 Hard Gate 失敗：
* **口語贅字零容忍**：100% 完整過濾講師的口語贅字（如「那個」、「然後」、「就是說」、「嗯」、「啊」、「呃」），保持句型流暢。
* **消滅同音錯字**：所有臺灣法律學術與實務術語必須精準辨識，不得出現同音錯字。
  * *錯誤範例*：格論、地政治、消滅實效、借名登記（寫成同音字）、投地登記、共耳、優購權。
  * *正確範例*：各論、地政士、消滅時效、借名登記、土地登記、共有人、優先購買權。
* **法條與字號格式標準化**：統一法條格式（如「民法第197條」）與字號格式（如「釋字第474號解釋」）。
* **Markdown 結構化排版**：必須依課程主題切換，主動劃分標題階層（#、##、###），並在關鍵段落自動加上重點粗體標記（如：`**【爭點】**`、`**【實務見解】**`）。

### 3. 板書影像偵測與 OCR 整合標準 (Blackboard & Visual Integration)
* **板書擷取準確度**：本地 OpenCV 必須精準捕捉講師寫字的畫面，穩定時才截圖，避免冗餘。
* **影像視覺解析（OCR）**：Gemini 必須正確將黑板上的手寫字、複雜法律法律關係圖（如：甲→乙→丙的代理、侵權關係）翻譯成結構化的 Markdown 文字筆記。
* **時戳精準嵌合**：板書翻譯筆記必須在正確的時間點插入 `.md` 講義逐字稿中，不得有時間軸錯位。
* **Obsidian 聯動**：圖片與解析檔案需正確保存於 C 碟的 `Obsidian_Vault/04_教材圖表校對/`。

### 4. 系統運行與防碰撞安全標準 (System Reliability)
* **API 容錯與進度即時存檔**：遇到 429 限制時自適應退避與輪替金鑰。每完成一個切片必須立刻將 manifest 寫回磁碟存檔，絕不重複消耗 API 額度。
* **硬體安全守護**：CPU 不暴衝、VRAM 不溢出、顯卡溫度守在 78°C 之下。
* **原始切片永久備份 (禁止刪除)**：單個任務順利完成後，【絕對禁止】刪除 A 碟暫存。必須自動將整個資料夾安全搬移至 `F:\chunks_backup\` 或 `E:\chunks_backup\` 備援。
* **期限審查 Hard Gate**：時效與期限審查零容忍（Hard Gate 閾值 = 1.00），一律由 DeadlineCalendar 計算，絕不可容忍任何偏差。
