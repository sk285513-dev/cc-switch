## v1 的目標

這個 v1 不是追求「全自動萬能 AI」，而是先做出一套 **能研究、能檢索、能摘要、能寫 code、能留下記憶** 的本地系統。對 16G VRAM 來說，最重要的是把「記憶」從 GPU 拆出去，讓 GPU 專心做推理、embedding、reranking 與 coding 任務。[web:2313][web:2316]

在這個版本裡，**RAGFlow** 負責知識攝取、分塊、索引、混合搜尋；**Obsidian** 負責人類可讀的長期記憶；**Ollama 模型群** 負責推理與 coding。[web:2324][web:2321][cite:2225]

## 各層的角色

## 1. 互動層

v1 不需要複雜前端，只要有一個能送出問題、上傳文件、查看結果的介面即可。Open WebUI 這類前端很適合當「研究入口」，不需要自己重做聊天 UI。[web:2311][web:2269]

如果未來你想要更強的開發代理介面，再考慮接 OpenHands；但 v1 可以先不要把所有東西疊太滿。[web:2286]

## 2. Agent / Workflow 層

這一層是 v1 的大腦，但要保持簡單。不要一開始就做多代理辯論或太複雜狀態機，只需要明確切四種任務：

- 研究分析。
- 文件摘要。
- coding。
- bugfix。

然後定義好每一種任務要走哪些步驟即可。[web:2290][web:2293]

## 3. RAGFlow 層

這是 v1 的核心新增元件。RAGFlow 的價值在於，它不只做向量搜尋，而是把：

- ingestion pipeline，
- parsing / cleansing，
- chunking，
- embedding，
- hybrid search（BM25 + vector），
- reranking

整合在一起。[web:2324][web:2321][web:2323]

這對研究型 AI 很重要，因為研究問題通常不是單一關鍵字，而是需要：先把資料吃乾淨、切對、找到、再重排，最後才讓模型根據證據回答。[web:2323]

## 4. Obsidian 層

Obsidian 在這個 v1 裡，**不是檢索引擎，而是人類可維護的長期記憶庫**。[cite:2225][web:2312] 你應該把：

- 研究筆記，
- 架構決策，
- 模型比較，
- 任務日誌，
- 成功 / 失敗案例

都寫在 Obsidian，然後再由 RAGFlow 去 ingest 這些內容。[web:2315][cite:2226]

## 5. 工具執行層

研究型 AI 不只是會回答，它還要會驗證。因此 v1 應保留：

- Python 執行。
- PowerShell。
- 測試命令。
- log 讀取。

但不要一開始就追求全桌面 GUI 自動控制；先把 terminal / script / test 這一層做好，實用價值最高。[cite:2274]

## 6. 模型層

模型層建議維持你目前已經較合理的分工：

- `gemma2:9b`：推理與摘要。
- `deepseek-coder`：寫 patch。
- `qwen2.5-coder:7b`：第二方案 / review。

這樣對 16G VRAM 來說相對現實，也保留研究分析與 coding 的分工空間。[web:2214][web:2164][web:2176]

## 資料流

### A. 研究問題

1. 你輸入研究問題。
2. Agent 判定需要查知識庫。
3. RAGFlow 對 Obsidian / PDF / 文件做 hybrid search。[web:2321]
4. 取回候選片段並 rerank。[web:2323]
5. Gemma2:9b 根據檢索結果做分析與摘要。[web:2214]
6. 最終結果寫回 Obsidian 任務日誌。[cite:2225]

### B. coding / bugfix

1. 你輸入 bug / 任務。
2. Agent 先查 RAGFlow，找過去案例、專案文件、相關 log。
3. Worker A / B 各自產生方案。
4. 工具層執行測試。
5. Gemma 做 Judge。
6. 最終 patch 與決策摘要寫回 Obsidian。

## 為什麼這版適合 16G VRAM

原因很簡單：

- **長期記憶不放進 GPU。** 它存在 Obsidian + RAGFlow 索引層。[web:2315]
- **GPU 只在需要時做推理。** 包含 embedding、reranking、回答生成與 coding。[web:2316]
- **模型分工而不是硬上大模型。** 這讓 16G VRAM 能維持可用的速度與穩定性。[web:2317][web:2214]

這比直接追求一顆超大模型包辦所有事，更適合長期使用。

## v1 不做什麼

為了避免系統複雜度失控，v1 先不做：

- 全桌面 GUI 自動控制。
- 多 agent 長鏈條協商。
- 自動寫入太多花俏 Obsidian 功能。
- 過度複雜的 workflow orchestration。
- 超大型模型 serving。

v1 的目的是先證明：
**這套架構能讓你本地做研究、檢索、摘要、coding，並留下可累積記憶。**

---

## v1 落地順序

1. 先保留現有 Ollama 模型層。
2. 補上 RAGFlow 做 ingestion / hybrid retrieval。[web:2324]
3. Obsidian 固定整理資料夾與筆記模板。[cite:2225]
4. 只保留最必要的 PowerShell / Python / 測試工具。
5. 先跑通「研究問題 → 檢索 → 分析 → 寫回日誌」這條主流程。
6. 再加 coding / bugfix workflow。

---

## v1 的一句話定義

**Obsidian 負責記住，RAGFlow 負責找回，Ollama 模型負責理解與實作。**

這就是最適合你目前 16G VRAM 條件下的研究型 AI v1 架構。
