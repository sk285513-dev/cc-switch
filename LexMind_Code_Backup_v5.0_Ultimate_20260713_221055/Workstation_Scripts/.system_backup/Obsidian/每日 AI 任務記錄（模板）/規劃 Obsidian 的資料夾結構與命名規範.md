# 好，請幫我規劃 Obsidian 的資料夾結構與命名規範

先給整體方向：你的 Obsidian 結構要對齊「研究筆記 / 程式碼與自動化 / 法律與決策 / 系統日誌」這幾條主線，讓每一類都能單獨變成一個 RAGFlow 資料集，同時又好維護、好回顧。下面是專門為你現在的架構（研究型 AI + RAGFlow + coding + 法律）設計的資料夾與命名規範。

***

## 頂層結構（Vault 根目錄）

建議頂層先固定這幾個大類：

- `00_系統架構`
- `01_研究筆記`
- `02_程式碼與自動化`
- `03_法律與案件`
- `04_任務日誌`
- `05_知識索引`

每一個都有明確角色：

- 00：整體 AI 系統與架構設計。
- 01：技術 / 理論 / 工具的研究與比較。
- 02：Python / PowerShell 腳本說明、架構、使用記錄。
- 03：法律條文、判決摘要、案件筆記。
- 04：每日任務與 AI 互動結果的時間軸。
- 05：索引、目錄、地圖頁（MOC），讓你人類自己找資料也方便。

***

## 00_系統架構

用來描述整個本地研究型 AI 的藍圖，這會是 RAGFlow 與模型都很重要的背景資料。

建議子資料夾：

- `00_系統架構/10_總覽`
- `00_系統架構/20_模型與代理`
- `00_系統架構/30_RAGFlow`
- `00_系統架構/40_自動化流程`

檔名命名建議：

- `2026-06-10_本地研究型AI_v1架構.md`
- `模型分工_gemma2_deepseek_qwen.md`
- `RAGFlow_部署與設定記錄.md`
- `Windows_自動化流程設計.md`

原則：

- 檔名前面可選用日期或版本，方便追蹤演進。
- 同一主題保持固定前綴，例如所有 RAGFlow 文件都以 `RAGFlow_` 開頭。

***

## 01_研究筆記

這裡放你對 RAG、向量資料庫、Agent 框架、模型比較等的研究筆記。

建議子資料夾：

- `01_研究筆記/RAG與檢索`
- `01_研究筆記/Agent與工作流`
- `01_研究筆記/模型與推理`

檔名命名建議：

- `RAGFlow_vs_R2R_比較.md`
- `Agentic_RAG_設計筆記.md`
- `本地模型選型_16G_VRAM.md`

原則：

- 每篇針對一個明確問題或主題。
- 標題用「主題式」命名，容易在 RAGFlow 裡當 metadata 使用。

***

## 02_程式碼與自動化

這是未來 RAGFlow「程式碼資料集」主要來源之一，因此結構要對齊我們剛才那份 chunking 規則表。

建議子資料夾：

- `02_程式碼與自動化/10_Python`
- `02_程式碼與自動化/20_PowerShell`
- `02_程式碼與自動化/30_腳本說明`
- `02_程式碼與自動化/40_錯誤與修復紀錄`

用法：

- 原始程式碼放在真正的 repo 內，這裡存的是**說明、設計與關鍵片段**，讓 RAGFlow 能檢索解說與範例。
- `腳本說明` 放每個重要腳本的「用途＋入口＋注意事項」。
- `錯誤與修復紀錄` 放 bug 描述、堆疊、解法，方便未來 RAGFlow 從這裡找類似案例。

檔名範例：

- `Python_環境檢查腳本_設計說明.md`
- `PowerShell_RAGFlow_安裝與啟動腳本_說明.md`
- `錯誤_Ollama_連線失敗_2026-06-10.md`

原則：

- 記得在筆記裡用標題分段：`## 腳本路徑`、`## 使用方式`、`## 典型錯誤`。
- 這些標題之後會是 RAGFlow chunking 的自然邊界。

***

## 03_法律與案件

這一塊是未來「法律 RAG 資料集」的主體。

建議子資料夾：

- `03_法律與案件/10_法條與規範`
- `03_法律與案件/20_判決與裁定`
- `03_法律與案件/30_案件筆記`
- `03_法律與案件/40_書狀草稿`

檔名規範建議：

- 法條整理：`法條_XX法_第YY條_整理.md`
- 判決摘要：`判決摘要_裁判字號_關鍵爭點.md`
- 案件筆記：`案件_案件代號_主題_YYYY-MM-DD.md`
- 書狀草稿：`書狀草稿_案件代號_類型_版次.md`

原則：

- 檔名裡一定要有關鍵識別：法規名稱 / 裁判字號 / 案件代碼。
- 內文標題固定形式：
    - `## 法條內容`
    - `## 立法理由 / 實務見解`
    - `## 本案適用與爭點`

這樣未來 RAGFlow 在做 hybrid search + rerank 時，可以用檔名 +標題 + metadata 就抓到正確內容。

***

## 04_任務日誌

這是你的「時間軸」與「AI 互動記錄」，日後作為長期記憶。

建議結構：

- `04_任務日誌/2026/2026-06/` 這樣按年份 / 月整理。

檔名：

- `2026-06-10_任務日誌.md`
- 每天一檔，搭配你現在已在用的 daily note 方式。

內文標題可固定為：

- `## 今日目標`
- `## 已完成任務`
- `## 問題與阻礙`
- `## AI 建議與決策`

這樣未來不管是 RAGFlow 還是你自己回顧，都能快速找到「哪天做了什麼、AI 提過哪些建議」。

***

## 05_知識索引

這一層是為了讓「你的人腦」和「RAGFlow」都能更好導航。

建議子資料夾：

- `05_知識索引/00_總索引`
- `05_知識索引/10_研究索引`
- `05_知識索引/20_程式碼索引`
- `05_知識索引/30_法律索引`

例子：

- `總覽_本地研究型AI_索引.md`：連到各主要架構與決策筆記。
- `索引_程式碼腳本與工具.md`：列表你所有常用 Python / PowerShell 腳本說明連結。
- `索引_法律主題與案件.md`：以主題（強執、家事、刑事）分組列案。

***

## 命名通用規則

1. **語言一致**：
    - 檔名用中文＋少量英文（model 名 / 工具名），避免全英文抽象名。
2. **固定前綴**：
    - 研究筆記：`RAG_`、`Agent_`、`模型_`
    - 架構相關：`架構_`、`系統_`
    - 法律相關：`法條_`、`判決_`、`案件_`、`書狀_`
3. **時間或版本放後面**：
    - `主題_YYYY-MM-DD.md` 或 `主題_v1.md`，不建議把日期或版本放最前面蓋掉主題。
4. **一檔一主題**：
    - 不在同一檔裡混三四個完全不同的主題，避免 chunking 時變成「萬用雜湊」。

***

## 對 RAGFlow 的好處

這種結構對你之後 RAGFlow ingest 有幾個直接好處：

- 每個資料集（研究 / 程式碼 / 法律）可以清楚對應到某幾個資料夾。
- 命名與標題本身就是 metadata，混合檢索時 keyword signal 很強。
- Chunking 可以直接以標題 / 段落為邊界，不需要每次再想一次。
